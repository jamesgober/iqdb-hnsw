# iqdb-hnsw v1.1.0

Fixes for search after deletes and for oversized parameters, plus a way to
reclaim deleted nodes.

## Added

- **`HnswIndex::compact()`** rebuilds the graph from the live vectors and
  frees every deleted node. Each vector keeps its insertion order (the
  tie-breaker) and its layer, so results stay deterministic. The cost is
  close to re-inserting the live vectors; with nothing deleted it returns at
  once.
- **`HnswIndex::tombstones()`** reports how many deleted nodes the graph
  still holds. A reasonable rule is to compact once it passes `len()`.

```rust
if idx.tombstones() > idx.len() {
    idx.compact()?;
}
```

## Fixed

- **Deletes no longer starve searches.** Deleted nodes filled the result
  beam and were removed only afterwards, so once the area around a query
  was mostly deleted a search could return nothing while plenty of live
  vectors remained. Deleted nodes are still walked through, because their
  edges keep the graph connected, but they never enter the beam or count
  toward it. The walk continues until it holds `ef` live nodes or has
  covered the reachable graph.
- **Filters are applied while walking.** A node that fails the filter is
  walked through but not collected, the same as a deleted one, so a
  selective filter returns every match the graph can reach, up to `k`.
- **`SearchParams::ef` is honoured.** It sets the base beam width; unset, the
  index uses `HnswConfig::ef_search` as before.
- **NaN distances rank last.** A NaN with its sign bit set used to sort
  before every number under `f32::total_cmp`.

## Security

- **Caller sizes no longer drive allocations.** Search buffers are sized
  from the beam width clamped to the number of stored nodes, so a huge `k`,
  `ef`, or `ef_construction` costs at most an exhaustive walk instead of a
  panic or an aborted process.
- **`m` is capped at 1024.** `HnswIndex::new` rejects larger values with
  `InvalidConfig`. Real graphs use 8 to 64; the cap stops a corrupt config
  from reserving terabytes on the first insert.
- **Node slots cannot wrap.** Inserting past `u32::MAX` stored nodes returns
  `InvalidConfig` instead of reusing an index; `compact()` frees the slots
  held by deleted nodes.

## Behaviour notes

- Searches that used to return fewer than `k` hits because of deletes or a
  filter now return up to `k`, and may walk more of the graph to find them.
- Results without deletes, filters, or `SearchParams::ef` are unchanged.

## Upgrading

Change the version to `1.1`. Nothing else is needed.
